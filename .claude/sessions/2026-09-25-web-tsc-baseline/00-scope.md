## 🔴 #2 ليس إصلاح أنواع — هو **prop كان بيتباع في الهوا**

الـ wrapper بيمرر `alignment={align}` لـ `Menu.Positioner`. و`@base-ui/react@1.4.1`
مالوش prop اسمه `alignment` أصلاً — الاسم الصحيح **`align`**:

```
node_modules/@base-ui/react/utils/useAnchorPositioning.d.ts:116
  align?: Align | undefined;
node_modules/@base-ui/react/utils/useAnchorPositioning.d.ts:5
  export type Align = 'start' | 'center' | 'end';
```

⇒ الـ prop **بيتجاهَل وقت التشغيل**، والقائمة بترسم بالـ default (`center`).

**و8 مواضع استدعاء كلهم بيمرروا `align="end"`:**
`subcontractors/page.tsx:460` · `team/page.tsx:575` · `team/org-chart:427` ·
`team/training:281` · `team/leaves:281` · `team/attendance:355` ·
`team/performance:304` · `team/safety:305`

🔴 **يعني إصلاح الخطأ ده بيغيّر شكل الـ UI في 8 قوائم** (من محاذاة وسط لمحاذاة
نهاية — وهي المقصودة أصلاً). **ده مش أثر جانبي، ده الإصلاح**: النية كانت مكتوبة
في كل موضع استدعاء وما كانتش بتتنفّذ.
**`Align` و`Side` المحليين متوافقين** (`'start'|'center'|'end'` و`'top'|'bottom'|'left'|'right'`
مجموعة فرعية من `Side`) ⇒ **صفر تغيير مطلوب على أي موضع استدعاء.**

## 🔴 قرار `WEB-STORE-001`: **حذف الإعلان، لا تنفيذه**

### المعطى الحاسم: **صفر مستهلك**
```
grep -rn "setUser" apps/web/src/
  → src/store/use-auth-store.ts:51   (الإعلان وحده)
```
ولا استدعاء واحد في الـ `src` كله. الترطيب والدخول والتسجيل **كلهم على `setSession`**
(`use-me.ts:46` · `use-auth.ts:38,91`).

### ليه الحذف

1. **تنفيذها = إضافة سطح API بلا مستهلك.** ودي نفس القاعدة اللي المشروع ده
   طبّقها بالفعل في `A-S7-1` («تصدير استباقي = سطح بلا مقابل»). الاتساق مع
   سابقة قائمة أفضل من اختراع مبرر جديد.
2. **الحذف بيقفل الفخ *بنيوياً*، والتنفيذ بيقفله *سلوكياً*.** بعد الحذف أي
   `useAuthStore.getState().setUser(...)` بيموت **وقت الترجمة**
   (`Property 'setUser' does not exist`). بعد التنفيذ بيشتغل صامتاً —
   وساعتها يبقى فيه **طريقتان** لتحديث الـ user (`setUser` و`setSession`)
   بدلالتين مختلفتين وبلا قاعدة مكتوبة تحكم أيهما يُستخدم. **الفخ الحالي فخ
   واحد؛ التنفيذ بيستبدله بغموض دائم.**
3. **التنفيذ مقدّمة للجزء (ب) من `R-4`** (تبديل hydration في `use-me.ts`) —
   وده **تغيير سلوكي** خارج نطاق session إصلاح tsc، ويستلزم ترقية (فحص #7أ فوق).
4. **والجزء (ب) نفسه ضعيف المبرر:** `R-4` بيسمّي مسح `pendingRegistration`
   على مسار `/users/me` **«side-effect غير مقصود»**. لكن `pendingRegistration`
   حيّ **فقط** بين خطوتَي التسجيل (`register` → `setup-workspace`)، والمستخدم
   ساعتها **مش داخل** ⇒ `useMe` بيرجع 401 والـ RouteGuard ما بيرطّبش أصلاً.
   و`useMe` بيشتغل تحت الـ dashboard وحده. ⇒ **نافذة التداخل عملياً صفر.**
   وحتى لو حصلت، مسح registration نصف مكتمل **فيه باسورد نصّي** لحظة تأكيد
   جلسة هو **بالظبط منطق `CVE-S1-001`** — يعني «العيب» المزعوم سلوك صحيح.

### ⚠️ ده يناقض الـ Fix المكتوب في `R-4` — ومقصود
`R-4` بيوصي صراحةً: *«نفّذ `setUser: (user) => set({ user })`»*.
**أنا بوصي بالعكس، والقرار النهائي لك.** المبرر إن `R-4` اتكتب وقت ما الجزءان
(أ) و(ب) كانا مربوطين كحزمة؛ فصلهما بيخلي (أ) قابلاً للحل بالحذف، و(ب) بيسقط
مبرره بعد فحص نافذة التداخل فوق.

### أثره على البنود القائمة
- **`WEB-STORE-001`: يُقفَل بالكامل** (الخطأ + الفخ الاتنين).
- **`R-4`: يُقفَل جزؤه (أ) فقط.** الجزء (ب) **لا يُقفَل بالصمت** — يتحوّل لبند
  مستقل بتوصية «يُغلَق كـ non-issue» + مبرر نافذة التداخل، **قرار للمستخدم**.

## المخاطر المعروفة
1. **`align` بيغيّر شكل 8 صفحات** — النتيجة **مرغوبة** (النية كانت مكتوبة وما كانتش
   تتنفّذ)، لكنها **تغيير مرئي ما حدش طلبه في الـ session دي** ⇒ **يُبلَّغ بسطر
   مستقل في التقرير**، لا يُدفَن تحت «إصلاح tsc».
2. **`vi.stubEnv` مع `afterEach` القائم** — الملف حالياً بيرجّع `prevEnv` يدوياً.
   لازم يتحوّل لـ `vi.unstubAllEnvs()` وإلا يبقى فيه آليتان للاستعادة.
   **vitest 3.2.6 مثبَّت ⇒ `stubEnv` متاحة.**
3. **حذف `setUser` قد يكسر كود مستقبلي مخطَّط** — مقبول وهو المطلوب: الكسر
   **وقت ترجمة** مع رسالة واضحة، بدل `undefined is not a function` وقت التشغيل.
4. **الـ build بياخد ~30 ثانية + type-check** — مفيش خطر، بس التحقق مش لحظي.
