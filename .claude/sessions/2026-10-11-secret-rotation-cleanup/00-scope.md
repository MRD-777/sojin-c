# Scope — تدوير المفتاح المسرَّب + تنظيف الأسرار من الريبو

## Mode: Standard
السبب: المهمة **إزالة بيانات اعتماد** من كود وتوثيق + تبديل قيمة في `.env` —
صفر تغيير في منطق الأمان نفسه، والملفات المتأثرة **سكربتات تشغيل يدوية بصفر
مستهلك** (متحقَّق: `grep` على كل `apps/` و`package.json` = لا أحد يستوردهما).

### فحص المعيارين (قاعدة #7أ — إلزامي في كل الـ modes)

| المعيار | الجواب |
|---|---|
| **1 — الدلالة:** بيغيّر دلالة حد أمني؟ | ❌ **لا.** مين يعدّي / إمتى الجلسة تموت / مين يشوف إيه — صفر تغيير. تدوير بيانات اعتماد **بيستبدل قيمة**، لا قاعدة |
| **1ملحق — اتجاه الفشل** | ✅ **يفشل مقفولاً** — المطلوب صراحةً إن السكربتات **تفشل برسالة واضحة** لو المتغير غايب (بدل ما تشتغل بمفتاح مدفون) |
| **2 — سطح هجوم جديد؟** | ⚠️ **صندوق واحد مُلامَس — والحكم إنه لا** |

**تفصيل المعيار 2 — لا أطمسه:**
`create-demo-users.mjs` **بيستخدم `auth.admin` بصلاحية service-role** ⇒ ملف على
مسار auth، و**عمره ما شاف هاكر**. ده الصندوق الأول من المعيار 2 حرفياً.

**ليه الحكم «لا» رغم كده:**
1. **صفر مستهلك** — الملفان مش مستوردين من أي module، ومش في أي script في
   `package.json`. مفيش **مسار طلب** يوصلهما ⇒ «سطح هجوم» بلا سطح.
2. **اتجاه التغيير = حذف** بيانات اعتماد وإضافة بوابة فشل — **مش إضافة مسار**.
3. الكود المنطقي للسكربتات **ما بيتغيرش**؛ بيتغير **من فين بيجيب المفتاح**.

🔴 **شرط ترقية صريح:** لو التنفيذ لقى نفسه **بيغيّر منطق** السكربتات (مش بس مصدر
المفتاح)، أو بيمسّ أي ملف في `apps/api/src/modules/auth/` ⇒ **وقف فوري + Deep**.

تدوير المفتاح الجديد في `.env`، تنظيف الأسرار المدفونة من السكربتين ومن
`BACKLOG.md`، فحص الريبو كامل، commit على فرع جديد، وإقفال session الـ
autonomous-harness كـ CANCELLED.

## 🔴 تلات حواجز — لازم قرارك قبل ما المخطط يكتب الخطة

### حاجز 1 — **البند 5 (push + PR) غير قابل للتنفيذ في البيئة دي**
متحقَّق منه عملياً دلوقتي:
```
git push --dry-run  →  fatal: could not read Username for 'https://github.com'
gh                  →  NOT installed
```
الحاوية دي **مفيهاش بيانات اعتماد GitHub ولا `gh` CLI**.

**اللي أقدر أعمله:** فرع جديد + commit **محلي** بس.
**اللي مش أقدر:** `git push` أو فتح PR.

**الخيارات:**
- **(أ)** أعمل الفرع والـ commit محلياً، وأديك الـ patch (`git format-patch`) أو
  أمر `push` جاهز تنفّذه انت. ← **توصيتي**
- **(ب)** تدّيني token بصلاحية `repo` — ⚠️ **بس ده نفس العيب اللي بنصلّحه**:
  بيانات اعتماد في الـ transcript. **منصحش بيه.**
- **(ج)** أسيب الشغل غير مكوميت وانت تعمله من جهازك.

### حاجز 2 — **البند 2 (restart + env-validation) مش هينجح هنا، ولسبب مش له علاقة بالمفتاح**
`apps/api/.env` الموجود **مفيهوش**:
- `DATABASE_URL` — **مطلوب ERROR** (`env-validation.ts:34`)، و`PrismaService:23`
  بيبني `PrismaPg(process.env.DATABASE_URL)` ⇒ مايقدرش يـ construct أصلاً
- `JWT_SECRET` — **مطلوب ERROR** (`env-validation.ts:82`, ≥32 حرف)

🔴 **والخطر هنا مش الفشل — الخطر إنه يُقرأ غلط.** لو شغّلت الباك إند وفشل،
السبب هيبقى **المتغيرين الناقصين**، لا المفتاح الجديد. **إسناد الفشل للمفتاح =
استنتاج كاذب**، وهو بالظبط نوع الخطأ اللي النظام ده بيحرس ضده.

**الخيارات:**
- **(أ)** تدّيني `DATABASE_URL` + `JWT_SECRET` ⇒ boot كامل حقيقي.
  ⚠️ `DATABASE_URL` فيه **باسورد قاعدة بياناتك** ⇒ هيدخل الـ transcript. **منصحش.**
- **(ب)** أتحقق من **السؤال الفعلي وحده**: أشغّل `validateEnvironment()` معزولة
  وأثبت إنها **مابتشتكيش من `SUPABASE_SERVICE_ROLE_KEY`** بالشكل الجديد، وأعلن
  صراحةً إن الباقي ما اتحققش. ← **توصيتي** — بيجاوب «هل الكود بيقبل المفتاح؟»
  من غير أي سرّ إضافي.
- **(ج)** تأجيل البند لسيرفرك.

### حاجز 3 — **شجرة العمل فيها شغل 4 sessions غير مكوميت**
```
 M CLAUDE.md                     ← القاعدة #11 + توسيع #7أ
 M .claude/sessions/BACKLOG.md   ← 6 بنود + شطب R-3/DBLMAP
?? 2026-08-08-.../05-principal-report.md + 06-meta-review.md
?? 2026-09-25-web-auth-404/ · 2026-09-25-web-tsc-baseline/ · 2026-09-27-autonomous-harness/
```
كله **موافَق عليه منك** في sessions سابقة، بس **محدش كوميته**.

🔴 **commit واحد هيبلع الاتنين** — إصلاح أمني + توثيق 4 sessions في diff واحد،
و**ده أسوأ شكل لمراجعة على موبايل**.

**توصيتي: فرع واحد، تلات commits منفصلة:**
1. `docs:` شغل الـ sessions السابقة (CLAUDE.md + BACKLOG + المجلدات)
2. `fix(security):` تنظيف الأسرار من السكربتين + BACKLOG
3. `docs:` إقفال autonomous-harness كـ CANCELLED

⇒ كل commit مقروء لوحده، والـ PR بيبان فيه التلاتة مرتبين.

## 🔴 ملاحظتان على البنود المطلوبة

### البند 6 — `auto:eligible` **مش موجود في الـ BACKLOG خالص**
```
grep -c "auto:eligible" BACKLOG.md  →  0
```
session الـ autonomous **وقفت عند الـ scope** ومكتبتش أي وسم. ⇒ **الشطر التاني
من البند 6 لا عمل له**. هسجّله «لا يوجد» صراحةً (قاعدة #11/إنفاذ 1) **ومش
هخترع وسوم عشان أشيلها**.

### البند 3 — `smoke-auth.mjs` بيستخدم مفتاح **ANON** وهو معطَّل دلوقتي
السكربت بيعمل `createClient(URL, ANON)` ثم `signInWithPassword`. الـ anon القديم
**مقفول**، وانت عملت **secret key بس** (مفيش publishable).

**قرار للمخطط:** السكربت يقرا من إيه؟
- **`SUPABASE_SERVICE_ROLE_KEY`** — ✅ **شغّال، متحقَّق منه عملياً** (`POST /auth/v1/token`
  بالـ secret رجّع 200 + توكن ES256). عيبه: مفتاح خطير في سكربت smoke.
- **`SUPABASE_PUBLISHABLE_KEY`** جديد — أنضف دلالياً، بس بيلزمك تعمل واحد.

**توصيتي: متغير منفصل `SUPABASE_SMOKE_KEY`** يقبل أي واحد منهم، **والسكربت
مايحتويش قيمة ولا default** — فالقرار بيبقى بيئي لا مدفون.
